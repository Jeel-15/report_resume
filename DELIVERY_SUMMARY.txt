✅ 3-Level Hierarchical Data Models
   ├─ UniversityReportTemplate (default sections for entire university)
   ├─ CollegeReportTemplate (override for specific college)
   └─ MajorReportTemplate (fine-tune for specific major)

✅ 6 API Endpoints (3 levels + utility)
   ├─ GET/PUT university-report-templates/<university_id>
   ├─ GET/PUT college-report-templates/<college_id>
   ├─ GET/PUT major-report-templates/<major_id>
   └─ GET majors/<major_id>/effective-report-sections (cascade resolver)

✅ Intelligent Cascade Logic
   └─ Major > College > University (with auto-fallback)

✅ Toggle-Based Customization
   └─ useUniversityDefault / useLevelAboveDefault flags

✅ Auto-Creation with Sensible Defaults
   └─ 5 default sections per university on first access

✅ Audit Trail & Timestamps
   └─ Track createdBy, createdAt, updatedAt for all changes

✅ Full Backward Compatibility
   └─ Old majors unaffected, system cascades gracefully

BEFORE (Embedded in Major):
├─ Every major manually configures sections ❌
├─ 100+ majors = 100+ section configurations 😫
├─ Hard to maintain university-wide standards 😰
├─ Impossible to bulk-apply changes ✗
└─ Lots of copy-paste duplication ♻️

AFTER (Hierarchical):
├─ Set once at University → applies to ALL ⚡
├─ Override at College for specific colleges 🎯
├─ Fine-tune at Major for exceptions 🔧
├─ Single change propagates everywhere 🚀
├─ Like Skillinc's grading system ✓
└─ Professional, industry-standard pattern ⭐
