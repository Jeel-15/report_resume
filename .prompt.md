# Assignment Studio: Phase-based AI Agent Prompt

Purpose
- Provide a single, repeatable prompt for an AI coding agent to execute one phase of the Assignment Studio implementation plan.

Usage
- Call the agent with a single `phase` specification (e.g., `phase: 1`).
- The agent MUST perform the three preconditions before making any code edits for the phase:
  1. Re-read all files listed in the phase's "Files to Read First" section.
  2. Follow all architectural constraints in Section A (SQLite adapter rules, auth, serialization, n8n secret verification, frontend tokens, naming conventions).
  3. Run the verification checklist described below and only proceed if it passes.

Inputs (agent invocation)
- phase: integer (1..N)
- plan_file: path to the implementation plan (defaults to `assignment_studio_implementation_plan.md` in repo root)
- files_to_read: optional explicit list of file paths to re-read (overrides plan list)
- run_tests: optional boolean (default: false)

Preconditions (mandatory, do not skip)
- Re-read the exact files in the phase's "Files to Read First" list. If any file is missing, abort and report which files are absent.
- Enforce Section A architecture constraints at all times. Use Python-level filtering for boolean fields, assign ListField values as whole lists, and never return raw Document objects — always serialize.
- Verify n8n callback endpoints check the `N8N_CALLBACK_SECRET` header/value as specified.

Verification Checklist (run before and after edits)
- Python: run `py -m py_compile` on any modified `.py` files.
- JS: run node syntax check (e.g., `node --check`) on any modified `.js` files present in `static/js`.
- Templates: run the project's `get_errors` or linter if available, or at minimum ensure no Jinja syntax errors by rendering changes carefully.
- Manual sanity: ensure any new model definitions are only added under `models/` and imported in `models/__init__.py` per naming conventions.

Agent Behavior and Output
- Before editing: list the files you will change and why. Wait for confirmation if the user requested it.
- Edit: apply minimal, targeted changes that respect existing style and conventions. Use the repo's `apply_patch` workflow.
- After editing: run the verification checklist again and report results.
- Return: a concise summary of changed files (paths), a short rationale for each change, and the verification results (pass/fail + logs).
- If tests or full app runs are not possible in the environment, state what checks were run and what remains for the user to validate locally.

Todo & Progress
- Use the workspace `manage_todo_list` to track steps for multi-step phases. Update statuses as you progress and mark the phase done only after the verification checklist passes.

Examples
- Minimal invocation (phase 1):
  - `phase: 1`
  - Agent must re-read `models/__init__.py`, `requirements.txt`, and `.env` (as listed in Phase 1 files) before creating `models/assignment_session.py` and `models/assignment_prompt.py`.

Ambiguities & Clarifying Questions
- If a phase's "Files to Read First" list references a file path that does not exist in the workspace, stop and ask the user which path to use.
- If a requested new dependency (e.g., `python-docx`) conflicts with the environment, report the conflict and suggest a local install command.

Notes for reviewers
- This prompt enforces the project's Section A constraints; any agent that cannot follow them must not proceed.
- Keep changes small and reversible. Prefer adding new files over changing core shared utilities unless necessary.
